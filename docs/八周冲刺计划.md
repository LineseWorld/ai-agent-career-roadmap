# 全职 8 周 AI Agent 转型冲刺计划

## 总体策略

八周内只推进一个作品：**企业智能工单 Agent（Service Desk Copilot）**。学习内容必须直接服务于这个项目或目标岗位，不同时建设第二个作品项目。

四条工作线同步推进：

1. 完成企业智能工单 Agent；
2. 补齐 Python、后端、Agent 和 RAG 知识；
3. 保持 C++、Linux、网络和数据库面试能力；
4. 从第 2 周开始持续投递并根据反馈修正方向。

建议每周工作 5.5～6 天，总投入 40～45 小时。每天保留运动和休息时间。

|---|---|---|---|

| 第 4 周 | 原生 Tool Calling Agent | 正式面试，投递 10～15 个 | Agent 能查询客户并创建工单 |
| 第 5 周 | LangGraph、人工确认、状态恢复 | 根据面试反馈补短板 | Agent 工作流 MVP 可演示 |
| 第 6 周 | 知识库 RAG、引用和拒答 | 定向联系公司与招聘人员 | 产品文档问答可用 |

## 每日时间模板

### 周一至周五

| 时间 | 内容 |
|---|---|
| 09:00～11:30 | 当前迭代编码，不看无关教程 |
| 11:30～12:00 | 运行测试、记录问题、提交 Git |
| 14:00～16:00 | 学习当天需求所需知识并立即实践 |
| 16:00～17:30 | 测试、文档、评测和代码整理 |
| 19:30～20:30 | C++/Linux/Python/Agent 面试准备 |
| 20:30～21:00 | 岗位筛选、投递或面试复盘 |

### 周六

- 上午完成本周可演示版本；
- 下午更新 README、截图、演示和评测结果；
- 晚上复盘投递数据并安排下周目标。

### 周日

原则上休息；最多用 1 小时规划下一周。

## 每周详细任务

### 第 1 周：Python 后端垂直切片

- 完成 Customer 模块工程化；
- 完成 Ticket 创建、查询和过滤；
- 掌握 FastAPI、Pydantic、依赖注入、异常处理和 pytest；
- 保证 Ruff、格式检查和测试通过；
- 完成简历初稿、30 个候选岗位和 3 分钟自我介绍。

### 第 2 周：后端 MVP 完整业务

- 完成 Ticket 状态机；
- 完成 Session 和 Message；
- 引入 PostgreSQL 和 SQLAlchemy；
- 增加迁移、分页、过滤和核心测试；
- 试投 5～8 个匹配岗位，收集简历反馈。

### 第 3 周：异步与可靠性

- 模拟服务状态、诊断和第三方 HTTP 系统；
- 学习 asyncio、异步 HTTP、超时、重试和并发控制；
- 为创建工单增加幂等键；
- 增加 request_id、结构化日志和审计记录；
- 投递 8～10 个岗位并开始模拟面试。

### 第 4 周：原生 Agent

- 熟悉模型 API、结构化输出、流式返回和 Tool Calling；
- 不使用 Agent 框架，手写工具调用循环；
- 实现查询客户、查询服务状态、查询历史工单和创建工单工具；
- 加入工具白名单、参数校验、最大步数和执行日志；
- 高风险操作必须人工确认。

### 第 5 周：LangGraph 工作流

- 使用 LangGraph 重构 Agent；
- 加入 Checkpoint、条件分支、人工确认、失败恢复和结果验证；
- 完成简单演示页面和第一版演示视频；
- 项目达到可写入简历、可在面试中展示的状态。

### 第 6 周：知识库 RAG

- 导入产品文档、错误码、FAQ 和脱敏历史工单；
- 实现解析、分块、Embedding、检索和来源引用；
- 增加关键词与向量混合检索；
- 无可靠依据时拒答；
- 建立初版评测集。

### 第 7 周：评测与生产化

- 构建不少于 30 条测试案例；
- 统计工具调用正确率、任务成功率、引用正确率、延迟和成本；
- 增加鉴权、审计、限流、超时和降级；
- 接入日志、指标和 Trace；
- Docker Compose 一键启动。

### 第 8 周：作品和面试闭环

- 整理架构、异常、安全、评测和部署文档；
- 录制 3～5 分钟最终演示；
- 准备 15 分钟项目讲解；
- 准备两个故障排查案例和一个技术选型对比；
- 集中投递，并准备薪资、离职原因和职业规划回答。

## 投递节奏

```text
第 1 周：整理 30 个候选岗位
第 2 周：试投 5～8 个，验证简历反馈
第 3 周：投递 8～10 个
第 4～8 周：每周投递 10～15 个高匹配岗位
```

岗位组合：

- 60%：AI Agent、大模型应用、RAG、Python AI 后端；
- 25%：AI 解决方案、交付、企业知识库和智能客服；
- 15%：C++、Linux、边缘 AI 或推理部署，作为风险对冲。

## 阶段判断点

第 4 周末检查：

- 已有面试：根据真实面试问题调整后四周；
- 投递无反馈：优先修改简历标题、项目描述和岗位匹配度；
- 有面试但技术未通过：统计高频短板，集中补最常出现的两项；
- 本地机会不足：同步扩大到周边城市、远程岗位及 C++/AI 交叉岗位。

## 不建议做的事

- 同时启动第二个作品项目；
- 连续数周只看视频、不写代码；
- 等项目全部完成才开始投递；
- 同时学习所有 Agent 框架；
- 把大量时间用于从零训练大模型；
- 因为转型而把自己包装成应届或初级工程师；
- 完全放弃 C++ 和 Linux 面试准备。
