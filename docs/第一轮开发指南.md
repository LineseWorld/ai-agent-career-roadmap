## 3. 每层职责

### `main.py`

只负责组装应用：创建FastAPI实例、注册路由和异常处理器。不在这里写客户或工单业务逻辑。

### `api/routes`

HTTP适配层：读取路径、查询参数和请求体，调用Service，再转换成HTTP响应。

它应该知道HTTP状态码，但不应该决定“客户暂停后能否创建工单”这种业务规则。

### `schemas`

Pydantic请求/响应模型，例如：

- `CustomerCreate`
- `CustomerResponse`
- `TicketCreate`
- `TicketResponse`
- `ErrorResponse`

这里负责输入格式、长度、枚举和范围校验。

### `domain`

核心业务概念和异常，例如：

- Customer、Ticket
- CustomerStatus、TicketStatus、Priority
- `CustomerNotFound`
- `CustomerSuspended`
- `InvalidTicketTransition`

该层不应该导入FastAPI。

### `services`

业务用例层，例如：

- 创建客户；
- 查询客户；
- 创建工单；
- 检查客户是否存在和可用；
- 后续执行工单状态转换。

Service不返回HTTPException，而是抛出领域异常。

### `repositories`

数据访问抽象：

- `interfaces.py` 定义Repository的能力；
- `memory.py` 用字典实现Sprint 1存储；
- 后续新增 `postgres.py`，Service无需重写。

### `tests/unit`

直接测试Service和业务规则，不经过HTTP。

### `tests/api`

通过FastAPI TestClient调用接口，验证状态码、JSON和错误响应。

## 4. 依赖方向

推荐保持：

```text
API → Service → Repository接口
                   ↑
              Memory实现
```

禁止：

```text
Repository → API
Domain → FastAPI
Service → MemoryRepository具体类
```

第一轮不需要使用复杂的依赖注入框架，普通构造函数和FastAPI `Depends`足够。

## 5. `pyproject.toml` 最小配置

```toml
[project]
name = "service-desk-copilot"
version = "0.1.0"
description = "Enterprise service desk agent learning project"
readme = "README.md"
requires-python = ">=3.11"
dependencies = [
    "fastapi[standard]",
    "pydantic>=2.0",
]

[dependency-groups]
dev = [
    "httpx",
    "pytest",
    "ruff",
]

[tool.pytest.ini_options]
pythonpath = ["src"]
testpaths = ["tests"]

[tool.ruff]
target-version = "py311"
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "I", "B", "UP", "RUF"]

[tool.ruff.format]
quote-style = "double"
indent-style = "space"
```

说明：依赖版本可以由 `uv add` 解析并写入，不需要手工追逐最新版本。

## 6. 建议初始化命令

在 `projects` 目录运行：

```powershell
uv init --app service-desk-copilot
cd service-desk-copilot
uv add "fastapi[standard]" pydantic
uv add --dev httpx pytest ruff
```

然后根据推荐结构调整 `src` 内的包名。

常用命令：

```powershell
uv run fastapi dev src/service_desk/main.py
uv run pytest
uv run ruff check .
uv run ruff check . --fix
uv run ruff format .
uv run ruff format . --check
```

## 8. 什么是Ruff

Ruff是Python代码检查与格式化工具，可以把它理解为：

```text
编译器警告检查的一部分 + 代码风格检查 + 自动格式化
```

它主要做两件事。

### `ruff check`

静态检查代码，常见问题包括：

- 未使用的import；
- 导入顺序混乱；
- 使用未定义变量；
- 一些容易产生Bug的写法；
- 可以使用现代Python语法简化的代码。

示例：

```python
import os  # 没有使用

def get_name():
    return user_name  # 没有定义
```

Ruff会报告这些问题。`ruff check . --fix` 可以自动修复安全可修复的问题，但修复后仍需查看diff。

### `ruff format`

统一缩进、空格、换行和引号布局，减少团队对格式的争论。

Ruff不能替代：

- pytest：它不运行功能测试；
- pyright/mypy：它不是完整类型检查器；
- Code Review：它不能判断业务逻辑是否正确；
- 安全审计：它不能保证系统安全。

## 9. 开发顺序

### Step 1：Hello API

创建 `main.py`，只实现 `/health`，确认应用可启动、OpenAPI可访问。

### Step 2：Customer垂直切片

依次完成：

```text
Customer Schema
→ Customer Domain Model
→ Repository接口和内存实现
→ CustomerService
→ Customer Route
→ Unit Test和API Test
```

不要先把所有目录填满再写功能。

### Step 3：Ticket垂直切片

用相同方式实现创建和查询工单，并验证客户不存在或暂停时不能创建工单。

### Step 4：统一错误响应

将领域异常统一转换成404、409等HTTP响应。避免Service直接抛 `HTTPException`。

### Step 5：质量检查

```powershell
uv run pytest
uv run ruff check .
uv run ruff format . --check
```

三条命令全部通过后，Sprint 1才算完成。
